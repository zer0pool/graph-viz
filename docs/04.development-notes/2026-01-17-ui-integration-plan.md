# Frontend UI 디자인 통합 가이드 (2026-01-17)

이 문서는 Figma 디자인을 Frontend 마이크로 프런트엔드(MFE) 아키텍처에 안정적으로 통합하기 위한 단계별 실행 계획을 담고 있습니다. 각 단계는 사용자 승인 후 진행하며, 기술적인 용어에 대한 설명을 포함하여 진행 과정을 쉽게 이해할 수 있도록 구성했습니다.

---

## 1단계: Tailwind CSS 인프라 구축 (Infrastructure)

**[의미]**: 본격적인 인형 옷 입히기를 시작하기 전에, **"옷감과 바느질 도구 세트"**를 준비하는 단계입니다.

- **Tailwind CSS란?**: 미리 정의된 수많은 디자인 조각들(예: '파란색', '여백 10px', '둥근 모서리' 등)을 조합하여 화면을 그리는 도구입니다. 코드를 훨씬 깔끔하게 유지하면서도 복잡한 디자인을 빠르게 구현할 수 있게 해줍니다.
- **작업 내용**:
  - 개발 도구 설치 및 설정 (Webpack, PostCSS 등)
  - Figma 테마 변수 정의 (브랜드 색상, 폰트 크기 등 미리 정의)
- **사용자 확인 지점**: 시각적으로는 바뀌는 것이 없어야 합니다. **"빌드가 잘 되고, 기존 화면이 깨지지 않고 잘 나오는가"**를 확인합니다.

## 2단계: 레이아웃 Foundation (Flexbox Migration)

**[의미]**: 집의 **"골조(뼈대)"**를 현대적인 방식으로 다시 세우는 과정입니다.

- **Flexbox란?**: 화면 안의 요소들을 고무줄처럼 유연하게 배치하는 기술입니다.
  - **현재 방식**: 고정된 수치나 투박한 정렬 방식을 사용하여, 브라우저 크기가 바뀌거나 요소가 추가될 때 레이아웃이 어긋나기 쉽습니다.
  - **Flexbox 방식**: "왼쪽 영역은 200px 고정, 나머지 오른쪽은 남은 공간을 다 채워라"라는 식의 똑똑한 배치가 가능합니다. 이를 통해 사이드바는 고정되고 메인 화면만 시원하게 스크롤되는 안정적인 구조를 만듭니다.
- **작업 내용**:
  - `AppLayout`의 뼈대를 Flexbox 구조로 변경.
  - 사이드바와 메인 콘텐츠 영역의 스크롤 분리.
- **사용자 확인 지점**: 전체적인 창 크기를 조절해도 **"사이드바와 위쪽 바가 고정된 채로 화면이 안정적으로 유지되는가"**를 확인합니다.

## 3단계: 사이드바 디자인 적용 (Sidebar Redesign)

**[의미]**: 집의 **"현관문과 안내판"**을 예쁘게 새로 만드는 과정입니다.

- **작업 내용**: Figma에서 정의한 아이콘과 메뉴 스타일을 입히고, 메뉴를 누르면 해당 페이지로 이동하도록 연결합니다.
- **사용자 확인 지점**: 왼쪽 메뉴의 아이콘들이 의도대로 보이고, 클릭했을 때 각 페이지로 잘 이동하는지 확인합니다.

## 4단계: 내비게이션 바 고도화 (Navbar Enhancement)

**[의미]**: 상단 **"게시판과 사용자 정보창"**을 세련되게 다듬는 과정입니다.

- **작업 내용**: 상단 바에 검색창과 사용자 프로필 사진(더미)을 배치하여 현대적인 웹 서비스의 느낌을 줍니다.
- **사용자 확인 지점**: 상단 바에 검색창이 예쁘게 들어갔는지, 전체적인 균형이 맞는지 확인합니다.

## 5단계: 통합 브레드크럼 (Breadcrumbs)

**[의미]**: 현재 내가 어디에 있는지 알려주는 **"이정표(발자취)"**를 설치하는 과정입니다.

- **Breadcrumbs란?**: '홈 > 테이블 > 상세조회' 처럼 이동 경로를 보여주는 바입니다. 길을 잃지 않게 도와줍니다.
- **작업 내용**: 어느 페이지에 있든 자동으로 경로를 계산해서 보여주는 컴포넌트를 추가합니다.
- **사용자 확인 지점**: 페이지를 옮겨 다닐 때마다 상단 이정표가 올바르게 바뀌는지 확인합니다.

## 6단계: 내비게이션 바 & 사이드바 통합 (Navbar Enhancements & Collapsible Sidebar)

**[의미]**: Google Cloud Platform Console 스타일의 **"접이식 메뉴와 브랜드 헤더"**를 구현하는 과정입니다.

- **작업 내용**:
  - `Navbar`에 햄버거 메뉴 버튼을 추가하고, `AppLayout`의 상태(State)와 연결합니다.
  - `Sidebar`가 접혔을 때(Collapsed) 텍스트를 숨기고 아이콘만 예쁘게 정렬되도록 CSS Transition을 적용합니다.
  - 전역 상태 관리를 통해 어느 페이지에서도 메뉴를 제어할 수 있게 합니다.
- **사용자 확인 지점**: 햄버거 버튼을 눌렀을 때 사이드바가 부드럽게 접히고 펼쳐지는지 확인합니다.

## 7단계: 테이블 랜딩 페이지 (Table Landing Page) - 상세 구현 계획

**[의미]**: **"핵심 데이터 대시보드"**를 구현하는 단계입니다. Figma 디자인을 그대로 코드로 옮겨오되, 유지보수성을 최우선으로 고려합니다.

### 7.1 설계 원칙 (Clean Code Strategy)

UI 코드가 복잡해지는 것을 막기 위해 철저하게 **"컴포넌트 분리"** 전략을 사용합니다.

- **Atomic Design**: 버튼, 카드, 뱃지 같은 작은 단위부터 먼저 만듭니다.
- **Separation of Concerns**: 데이터(Mock Data)와 UI(View)를 분리합니다.

### 7.2 상세 구현 계획

#### A. 인프라 및 UI Primitives (재사용 가능한 부품 만들기)

참조 코드(`shadcn/ui` 패턴)를 기반으로 우리 프로젝트에 맞는 경량화된 컴포넌트를 `src/components/ui`에 구축합니다.

- `Card`, `Button`, `Badge`, `Input`: Tailwind CSS 조합으로 구현하여 무거운 라이브러리 의존성을 제거합니다.
- `Table`: 데이터 테이블의 헤더, 바디, 행 스타일을 미리 정의하여 일관성을 확보합니다.

#### B. 컴포넌트 구조 (Component Architecture)

거대한 `TablesPage.tsx` 하나에 다 때려박지 않고, 의미 단위로 파일을 쪼갭니다.

1. **`TableLanding.tsx` (Root)**: 페이지의 뼈대와 헤더, KPI 카드 섹션을 담당합니다.
2. **`TrendsSection.tsx`**: `recharts` 라이브러리를 사용해 3개의 라인 차트(테이블 수, 용량, 이슈)를 그립니다. 차트 설정 코드가 길기 때문에 별도 파일로 분리하여 메인 로직의 가독성을 높입니다.
3. **`TopLists.tsx`**: '용량 상위 10개'와 '활동 상위 10개' 카드를 담당합니다. 데이터 가공 로직(정렬, 점수 계산)을 이 컴포넌트 내부나 `utils`로 격리합니다.
4. **`DatasetsTable.tsx`**: 메인 데이터 목록을 담당합니다. 필터링 및 페이지네이션 로직이 들어갈 곳입니다.

#### C. 데이터 흐름 (Data Flow)

현재는 백엔드 API가 준비되지 않았으므로 **Mock Data**를 사용하지만, 추후 API 연동이 쉽도록 데이터를 한곳(`TableLanding` 또는 별도 상수 파일)에서 정의하여 Props로 내려주는 방식을 채택합니다.

## 작업 협업 규칙

1. **Accept 확인**: 각 단계의 '검증'이 완료되어 사용자님의 승인이 떨어진 후에만 다음 단계로 넘어갑니다.
2. **진행 상황 공유**: 작업 중 궁금한 점이나 기술적인 선택이 필요한 경우 즉시 소통하여 리소스 낭비를 방지합니다.
