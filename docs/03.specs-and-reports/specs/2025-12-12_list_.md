요약

List View에 “전체 lineage(Upstream/Downstream 전체)”를 조회·표시하는 기능을 추가하고, Cytoscape(Graph)와 Detail Panel 간의 상태 동기화 구조를 설계한다.
그래프는 렌더링 가능한 범위에서 부분 뷰를 유지하고, 리스트는 그래프보다 더 넓은 전체 lineage 계층 뷰를 제공한다.

1. 목적

선택된 테이블/작업 기준

전체 업스트림·다운스트림 lineage 목록을 계층(depth) 기반으로 조회

CSV 다운로드 지원

그래프는 전체 DAG를 그릴 수 없기 때문에

그래프는 “요약 뷰(1~N hops)”에 집중

List View에서 전체 lineage 탐색 기능 제공

Graph ↔ List ↔ DetailPanel 간

상태(state) 기반 동기화 구조 확립

선택/확장/조회 행동이 서로 자연스럽게 연결되도록 설계

2. 기존 문제점

그래프 노드가 많을 경우 Cytoscape 렌더링 부담이 커져 브라우저가 멈춤.

현재 List View는 “그래프에 표시된 노드만” 보여주므로 전체 lineage 파악이 어려움.

사용자 요구:

전체 lineage를 계층적으로 보고 싶다

그래프는 요약 뷰로 충분

리스트는 전체 깊이를 보여주고 CSV로 내보내고 싶다.

3. 기능 요구사항 (Requirements)
R1. 전체 lineage 조회 기능

버튼: Load full lineage

결과:

upstream[], downstream[]

depth, parent 정보 포함

최대 수천 개 노드도 렌더링 가능해야 함

R2. 리스트 화면은 “테이블 기반 계층 구조” 유지

기존 List View 디자인과 동일한 스타일

depth 기반 들여쓰기 적용

upstream / downstream 섹션 분리

R3. CSV Export

full lineage 조회 후 CSV 다운로드

full lineage 미조회 상태에서는 “current graph nodes” 기준 CSV 다운로드

R4. Graph ↔ List ↔ Detail Panel Sync

공통 SelectionState: 선택 노드 단일 관리

공통 LineageState: graph nodes + 전체 lineage 관리

그래프에서 클릭 → 리스트/패널 갱신

리스트에서 클릭 → 그래프 하이라이트, 패널 갱신

패널은 항상 current selection 기반으로 표시

R5. 점진적 그래프 확장

그래프는 전체 DAG를 한번에 렌더링하지 않음

“Expand Graph” 버튼으로 필요한 부분만 확장

확장 결과도 ListView의 Current Nodes 테이블에 반영됨

4. API 스펙 (요약)
4.1 전체 lineage 조회

GET /api/v1/lineage/tables/{full_name}/hierarchy

Response JSON:

{
  "upstream": [
    { "id": "SRC_TABLE", "name": "SRC_TABLE", "type": "TABLE", "depth": 3, "parent": "L1" }
  ],
  "downstream": [
    { "id": "AGG_JOB", "name": "AGG_JOB", "type": "JOB", "depth": 2, "parent": "CLEAN" }
  ],
  "root_nodes": [],
  "leaf_nodes": []
}

4.2 그래프 확장 조회 (기존 유지)

GET /api/v1/graph/expand?nodeId=x&direction=upstream|downstream

6. State Sync 구조 설계
6.1 SelectionState (선택 노드 공유)

어떤 UI에서 선택하든 공통 저장소에 기록

모든 뷰(Graph, List, Panel)가 subscribe

selectionState.set({ id, label, type, source });


동기화 흐름:

그래프 클릭 → selectionState → List row highlight + DetailPanel 표시

리스트 클릭 → selectionState → 그래프 노드 highlight + DetailPanel 표시

6.2 LineageState (graph data + full lineage data)

그래프 노드/엣지

Full lineage upstream/downstream

각 컨트롤러는 이 state를 구독해서 화면을 갱신

갱신 시나리오

그래프 확장 → lineageState.setGraphData()

full lineage API 호출 → lineageState.setFullLineage()

GraphController, ListController 모두 자동 반영

7. GraphController 동작 정리

Cytoscape 초기화

Node click → "graph" source 로 selectionState 갱신

Expand Graph 실행 → neighbor 노드/엣지 조합 → lineageState 갱신

lineageState.subscribe → 그래프 재렌더링

8. ListController 동작 정리

lineageState.subscribe → Current nodes 테이블 자동 업데이트

Load full lineage 클릭 → /hierarchy 호출 → lineageState.setFullLineage

Full lineage 테이블 온전히 렌더링

Row click → selectionState 갱신

CSV 다운로드 → full lineage 여부로 데이터 선택

9. DetailPanel 동작 정리

selectionState.subscribe

선택된 노드 id 기준으로 Detail API 호출

Panel UI 업데이트

Graph/List에서 어떤 방식으로 선택되더라도 Panel은 자동으로 갱신됨.

10. 데이터 흐름 요약 다이어그램
       [Graph View]
             │  click/select
             ▼
       selectionState  ◄── click/select ─── [List View]
             │
             ▼
       [Detail Panel]

Graph expand ─────► lineageState ─────► Graph redraw
                               └──────► List (Current nodes) update
                               └──────► List (Full lineage) update


Graph는 부분 렌더링,
List는 전체 lineage 렌더링,
Detail은 선택된 노드 정보 표시.

11. 장점
1) 브라우저 성능 문제 해결

그래프는 더 이상 전체 DAG를 그리지 않음

리스트는 계층 기반 테이블 렌더링으로 수천 노드까지 처리 가능

2) 사용자 경험 개선

전체 lineage를 한 번에 파악 가능

CSV export로 분석 가능

그래프-리스트-패널 동기화 자연스러움

3) 구현 구조 단순화

상태 주도(state-driven UI) 구조

React 전환 시에도 동일 패턴 그대로 사용 가능

12. 향후 확장 가능성

Tree Table 형태로 fold/unfold 지원

upstream/downstream 필터

depth 제한 옵션

lineage diff 기능(버전 비교)
